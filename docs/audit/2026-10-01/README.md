## 1. Загальний вердикт

Проєкт зрілий і працює, але має три системні проблеми, що відповідають вашим трьом запитам:

1. **Контекст перекладу дорогий і частково зламаний.** Один рядок на 12 токенів коштує ~3 000 токенів запиту (90 % — статика, що не кешується); чанк із 12 рядків — ~5 500 токенів, 56 % статики. Дві «фічі» з документації не працюють узагалі: сесії провайдера (прапорець записується в один об'єкт, читається з іншого) і `NarrativeLedger` (жодного виклику `record_*` у коді — «канон» ніколи не накопичується). Сусідні рядки для контексту беруться з неправильних індексів при перекладі виділення.
2. **Глосарій будується без пам'яті про власні рішення — ваша скарга підтверджена структурно.** Кожен AI-запит (sweep → describe → translate) бачить лише свою одиницю; жоден етап не отримує вже ухвалених перекладів. Нормалізація лише регістр/пробіли; `add_entry`/`update_entry` шукають точний `original`, а `get_entry` — нормалізований, через що утворюються дублі (`Hylian Shield`/`Hylian shield`) і мовчки губляться оновлення. На реальних даних (`glossary.json`, 612 записів): 18 груп колізій (`Rupee/Rupees`, `Clawshot→Кігтемет` vs `Clawshots→Подвійні гаки`, `Postman→Листоноша/Поштар`), 19 «родин» термінів із розбіжним перекладом спільного кореня (`Ooccoo→Уку/Окку`, `Reekfish→гнилка/Рікфіш`). Порядок результатів паралельних воркерів недетермінований → глосарій щоразу трохи інший.
3. **Плагінна база: текстова половина адекватна, форматна — ні.** `BaseGameRules` має 54 хуки з безпечними дефолтами, `plugins/common` вже тримає рушій правил; текстовий плагін для нової гри — ~150 рядків. Але розширення файлів (`.json/.txt/.bmg/.arc`) зашиті в хост у 5 місцях, UI напряму імпортує `plugins.zelda_bmg` (10 місць), хост читає приватні атрибути двох плагінів (`original_keys`, `last_loaded_bmg`), 16 недокументованих duck-typed хуків, `eval()` на ключах project_settings. Гра з власним табличним форматом (PS1 `.bin`) відхиляється до того, як плагін узагалі спитають. Немає ні валідатора, ні шаблону, ні smoke-тесту; `plugins/DEVELOPER_GUIDE.md` суттєво хибний (не ті сигнатури, вигаданий формат `font_map.json`).

Додатково: транспорт до проксі має три несумісні режими retry (блочний переклад взагалі не ретраїть і ігнорує `Retry-After`), три різні «чистильники» JSON із відтворюваними помилками, а сам проксі існує у двох версіях, що розійшлися (моноліт `gemini_web2api.py`, який запускає `run.bat`, ігнорує `think` і має нескінченну рекурсію в обробці помилок → HTTP 500 замість 429/502).

## 2. Що з'ясувалось про стан репозиторію

- **Тести:** 2353 passed / 83 failed / 130 errors (Linux, offscreen). ~190 з 213 збоїв — **артефакт мого пакування** (я випадково вирізав `core/mempalace*` фільтром, задуманим для `mempalace_local.db`; на вашому диску пакет є, 64 файли в git). Реальні проблеми: 1 детермінований segfault (`test_variations_list_delegate_paint`), ~11 xdist-флейків (лямбди на знищених віджетах у `tools/bfn_editor/window_ui_mixin.py:133-141`, словник за `id()`), 2 Windows-only тести без skip, 9 тестів залежать від некомічених ресурсів (`.dic/.aff`, іконки). Сюїта пише `settings.json`, `app_debug.txt`, `ai_traffic.log` у корінь репо.
- **`ruff check .`:** 0 помилок поза `gemini/` (стара копія коду 2025-05, 133 файли, в `.gitignore`, але ламає `test_ruff_check` локально). 681 `except Exception`, 168 `try/except: pass`, 73 функції > 150 рядків (`run()` воркера — 746).
- **Залежності:** `PyQt6==6.6.1` без пінa `PyQt6-Qt6` → чиста інсталяція тягне Qt 6.11 і PyQt6 не імпортується.
- **Переноси рядків:** 594 CRLF / 393 LF `.py`, 51 файл із BOM, немає `.gitattributes` → ваш `git diff` показує 715 файлів замість 25.
- **Дані користувача не пишуться атомарно:** `settings.json`, `session_state.json`, `*.uiproj`, глосарій, вихідні переклади — `json.dump` прямо у файл; падіння посеред запису = порожній файл.
- **Потоки:** 4 з 15 `QThread`-воркерів без кооперативного скасування; `sync_dialog.py:248,258` викликає `terminate()` на воркері з HTTP+файловим I/O; `safe_shutdown_thread` від'єднує сигнали **до** зупинки потоку й робить `deleteLater()` на ще живому потоці.
- **`plugins/MagicMock/` (1242 файли)** — наслідок `plugin_settings.py:248`: шлях `plugins/<active_game_plugin>/aliases.json` відносно CWD; у тестах `active_game_plugin` був MagicMock. Тобто плагінна тека — змінний стан користувача.
- **Документація:** wiki (EN+UK) точна й синхронна — це добре. Проблема в усьому довкола: README (16.6k токенів) + GEMINI.md (7.5k) = 25k токенів лише на вхід; логи `CHANGELOG/walkthrough/AUDIT/plan/task` — ~240k токенів у корені, українською (×1.7 дорожче), 0 відкритих пунктів у plan/task. Немає `AGENTS.md`/`CLAUDE.md`; правило Graphify-first викладено в 4 місцях трьома різними способами (одна з версій веде до читання 71k-токенного `GRAPH_REPORT.md`). 7 із 13 перевірених фактів у README/GEMINI застарілі (меню «Preferences», DeepL, мертві шляхи, дві версії в GEMINI.md). `.graphifyignore` відсутній → 28 % вузлів графа — тести, ще ~1.6k — markdown-логи.
