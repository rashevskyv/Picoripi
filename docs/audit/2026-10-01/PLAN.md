# Picoripi — Execution Plan (audit 2026-10-01)

Audience: the executing model (any tier). Written to be followed **one work package (WP) at a time** with minimal context.
Source of truth for details: the six reports in this folder (`A_…F_…`). Each task below names the report section with `file:line` evidence — read **only that section**, not the whole report.

## How to work (read once)

1. Start every session with `git status --short`; never revert files you did not touch. Unknown modified files are the user's work.
2. One WP per session. Inside a WP, tasks are ordered; do not reorder unless a dependency note says it is safe.
3. For every task: read the referenced report section → read the named files (only the ranges named) → implement → run the named verification → tick the box in `TASKS.md` → one `CHANGELOG.md` line.
4. Tests: `QT_QPA_PLATFORM=offscreen PYTHONPATH=. python -m pytest -n auto -q tests/` (Windows: `$env:PYTHONPATH="."; .\venv\Scripts\python.exe -m pytest -n auto -q tests/`). A WP is done only when the suite is green and `ruff check .` is clean.
5. Do not refactor beyond the task. If you find something else broken, add one line to `docs/OPEN_ITEMS.md` and move on.
6. Graphify: `graphify explain "<Name>"` / `graphify path "A" "B"` for navigation; `graphify update .` after a WP that adds/moves modules. Never read `GRAPH_REPORT.md` whole.
7. Report to the user in Ukrainian; write code comments, docs for agents and commit messages in English.
8. Commit per task or per small group of tasks, message `wp<N>: <task id> <summary>`. Bump the version only at the end of a WP (`scripts/bump_version.py`).
