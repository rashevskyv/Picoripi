# Усунення несправностей

**Мова:** [English](../Troubleshooting.md) · Українська

Ця сторінка перелічує типові проблеми. Знайдіть свій етап у списку, а потім симптом. У кожному рядку є причина і спосіб виправлення.
Повідомлення наведено так, як Picoripi показує їх англійською.

## Встановлення

| Симптом | Причина | Що робити |
|---|---|---|
| `setup.bat` зупиняється з повідомленням `Microsoft Visual C++ 14.0 or greater is required`. | Деякі пакети компілюються, а компілятора C++ немає. | Встановіть Microsoft C++ Build Tools з набором **Desktop development with C++**. Знову запустіть `setup.bat`. |
| `setup.bat` падає на кроці Python. | Picoripi потребує Python 3.10 або новіший. | Встановіть новіший Python. Знову запустіть `setup.bat`. |
| `run.bat` довго не показує вікно. | Перший запуск повільний. | Зачекайте близько 15 секунд. Не запускайте програму двічі. |
| Запуск зупиняється з `DLL load failed while importing QtCore`. | Немає Visual C++ Redistributable, або інша програма має свій Qt. | Встановіть Microsoft Visual C++ Redistributable 2015-2022 (x64). Знову запустіть `setup.bat`. |

## Перший запуск

| Симптом | Причина | Що робити |
|---|---|---|
| Picoripi питає, де зберігати дані. | Теку даних ще не вибрано. | Виберіть порожню теку, у яку можна писати. Налаштування та список проєктів зберігаються там. |
| Інтерфейс не українською. | Мову інтерфейсу не встановлено. | Відкрийте меню **Мова** і виберіть українську. |

## Майстер (Новий проєкт)

| Симптом | Причина | Що робити |
|---|---|---|
| У статусі файлу: **Потрібен файл ключів**. | Файл зашифровано. | Натисніть **Отримати ключі з типового джерела** або **Додати файл ключів для ...**, щоб вибрати власний файл. |
| `Picoripi не може під’єднатися до джерела. Перевірте з’єднання і спробуйте знову.` | Немає з’єднання, або брандмауер чи проксі блокує завантаження. | Перевірте з’єднання і спробуйте знову. Або виберіть файл. |
| `У джерелі немає файлу ... Можливо, джерело переїхало.` | Типове джерело переїхало або його прибрано. | Змініть джерело на вкладці **Ключі консолей** або виберіть файл. |
| `Джерело відхилило запит (HTTP 429). Спробуйте пізніше.` | Джерело на деякий час обмежує запити. | Спробуйте пізніше або виберіть файл. |
| `Файл ... не відповідає запису джерела. Його не збережено.` | Завантаження пошкоджено, або джерело змінилося. | Спробуйте знову або виберіть файл. |
| У статусі: **Не читається: додайте папку**. | Плагін гри не читає цей тип файлу. | Приберіть файл. Додайте розпаковану теку гри кнопкою **Додати папку...**. |
| У статусі: **Ця гра не розпізнає файл**. | Файл не належить цій грі, або плагін не читає цей формат. | Приберіть файл. Або встановіть його **Роль** і **Платформу** вручну. |
| `Give every file a role.` | Хоча б в одного файлу немає ролі. | Виберіть роль для кожного файлу. Натисніть **Застосувати**. |
| `Two files have the role ...` | Два файли мають одну роль. Повторюватися може лише DLC. | Дайте іншому файлу власну роль. |
| `Not enough free space on ...` | На диску мало місця для розпакування гри. | Звільніть місце на цьому диску або виберіть теку проєкту на іншому диску. |
| `Choose the game.` / `Give the project a name.` / `Add at least one file.` | Порожнє обов’язкове поле. | Заповніть поле. Знову натисніть **Створити проєкт**. |
| `No key file was chosen. Nothing was created.` | Ви закрили вікно вибору файлу ключів. | Почніть знову і виберіть файл ключів. |
| Вашої гри немає в списку **Гра**. | Для неї немає плагіна в Picoripi. | Див. [Підтримувані ігри](Supported_Games.md). |

## Відкриття проєкту

| Симптом | Причина | Що робити |
|---|---|---|
| `Project Load Failed` з текстом `Failed to load project from: ...`. | Файл проєкту не читається, або завантаження зупинилося з причиною. | Прочитайте причину під шляхом. Якщо файл проєкту пошкоджено, відновіть копію. |
| `Project Not Found` з текстом `Project file not found: ...`. | Теку проєкту перемістили або видалили. Picoripi також прибирає його зі списку недавніх. | Знайдіть теку. Відкрийте її через **Файл → Відкрити проєкт...** (`Ctrl+O`). |
| У рядку: **Плагін відсутній**. | Теки плагіна гри немає в `plugins`. | Поверніть відсутню теку в `plugins`. Відкрийте проєкт знову. |
| У рядку: **Потребує уваги**. | Шлях або файл проєкту неправильний. Панель деталей називає проблему. | Прочитайте текст під списком, наприклад `The original files path does not exist.`. Виправте цей шлях. |
| У рядку: **Немає файлу** або **Не читається**. | Файлу проєкту немає, або його не можна прочитати. | Відновіть файл проєкту з копії. |
| `N blocks have no translation file yet.` | Проєкт новий, або частину блоків ще не збережено. | Це нормально для нового проєкту. Перекладіть блоки і збережіть. |

## Редактор

| Симптом | Причина | Що робити |
|---|---|---|
| Список рядків порожній. | Увімкнено **Лише незбережені**, а змін немає. | Вимкніть **Лише незбережені**. Після перезапуску вона вимкнена. |
| Останньої правки немає після перезапуску. | Правку не збережено. | Натисніть `Ctrl+S` перед закриттям. Перевірте параметр **Відновлювати незбережений сеанс під час запуску**. |
| З’являється `Відхилити незбережені зміни?`. | Ви перезавантажуєте або закриваєте з незбереженими змінами. | Натисніть **Скасувати**, потім збережіть. |
| У списку: **Помилка тегу**. | Тег у тексті не збігається з оригіналом. | Виправте тег. Див. [Ширина, шрифти і теги](Width_Fonts_Tags.md). |
| У списку: **Перевищено ширину**. | Рядок ширший за ліміт гри. | Скоротіть рядок. Див. [Ширина, шрифти і теги](Width_Fonts_Tags.md). |
| Збереження зупиняється: `... changed outside Picoripi. Reopen the project before saving.`. | Файл змінився на диску після того, як Picoripi його прочитав. Текст на екрані застарів. | Відкрийте проєкт знову. Потім відредагуйте і збережіть. |
| Редактор працює повільно. | Великий проєкт завантажується, або працює фонове завдання. | Зачекайте, поки прогрес зупиниться. Якщо не допомагає, надішліть журнал (див. нижче). |

## Переклад ШІ

| Симптом | Причина | Що робити |
|---|---|---|
| `AI provider is disabled. Configure it in AI Translation settings first.`. | Провайдер ШІ вимкнено. | Відкрийте **Налаштування → AI-переклад**. Виберіть провайдера. |
| **Перевірити провайдера** показує `Connection failed!`. | Проксі або кінцева точка не працює, або адреса хибна. | Запустіть проксі. Для Gemini Web2API перевірте адресу `http://127.0.0.1:8081/v1`. Перевірте знову. |
| Пакетний переклад дуже повільний або запити падають. | **Паралельні запити:** більше, ніж акаунтів у проксі. | Встановіть **Паралельні запити:** рівним кількості акаунтів. Зайві запити чекають на паузу. Див. [Переклад ШІ](11_AI_Translation.md). |

| Симптом | Причина | Що робити |
|---|---|---|
| **Зібрати**, **Експорт** і **Запустити в емуляторі** вимкнені. | Плагін гри не оголошує ціль збірки. | Перевірте цілі збірки в [Підтримувані ігри](Supported_Games.md). Деякі ігри збираються робочим скриптом. Див. [Збірка і тестування](Build_and_Test.md). |
| `No build target yet. Add a project with a build target first.` | У діалозі емулятора немає цілі збірки для відкритого проєкту. | Відкрийте проєкт, у якого є ціль збірки. Потім запустіть його. |

| Збірка зупиняється з помилкою. | Файл з джерельним або перекладеним текстом неправильний. | Прочитайте повідомлення. Воно називає файл. Виправте його і зберіть знову. |

## Емулятор

| Симптом | Причина | Що робити |
|---|---|---|
| Емулятор не запускається. | Команду платформи не задано, або шлях хибний. | Перевірте команду платформи в **Налаштуваннях**. Перевірте шлях до емулятора. |
| Зібраний мод не завантажується в емуляторі. | Мод не встановлено. Тека LayeredFS або Luma сама не завантажується. | Встановіть зібрану теку в емуляторі. Деякі ігри потребують кроку встановлення в команді. |

## Тека даних і налаштування

| Симптом | Причина | Що робити |
|---|---|---|

## Передача

| Симптом | Причина | Що робити |
|---|---|---|
| `This file is not a shared Picoripi project.` | Ви відкрили інший файл. | Виберіть `.zip`, який створила кнопка **Поділитися проєктом...**. |
| `This shared project was made by a newer Picoripi. Update Picoripi to import it.` | В іншої людини новіша версія. | Оновіть Picoripi. Імпортуйте знову. |

## Журнали

Picoripi пише журнал у файл `app_debug.txt`. Типово він лежить у теці програми.

1. Відкрийте **Файл → Налаштування (`Ctrl+P`)**. Відкрийте вкладку **Журнал**.
2. Увімкніть **Увімкнути ведення логу у файл**. Увімкніть **Увімкнути ведення журналу в консолі**, якщо хочете бачити журнал у консолі.
3. У полі шляху до файлу журналу залиште текст порожнім, щоб використовувався типовий `app_debug.txt`. Або введіть свою теку й назву файлу.
4. Повторіть проблему. Потім відкрийте `app_debug.txt`.

## Повідомлення про помилку

1. Відкрийте сторінку задач: <https://github.com/rashevskyv/Picoripi/issues>. Спершу знайдіть таку саму проблему.
2. Опишіть, що ви робили, крок за кроком. Напишіть, що очікували і що сталося.
3. Скопіюйте повний текст повідомлення з вікна.
4. Додайте `app_debug.txt` за час проблеми.
5. Вкажіть версію Picoripi, версію Python і версію Windows.

**Не додавайте** файли гри, захищені авторським правом дампи або свій текст перекладу. Перед завантаженням приберіть з журналу особисті шляхи.

## Типові ситуації

**Усе ламається після оновлення.**
- Знову запустіть `setup.bat`. Він оновлює пакети в `.venv`.
- Якщо не допомогло, додайте журнал до звіту.

**Я помилився і зберіг зміну.**
- Picoripi не відміняє збережений файл. Використайте копію теки проєкту, яку зробили раніше.
- Перед великими змінами робіть копію теки проєкту.

**Програма повільна лише з одним проєктом.**
- Запишіть назву проєкту і етап (редактор, збірка або ШІ).
- Надішліть журнал. Назвіть проєкт у звіті, але не його текст.

**Проблеми немає в списку.**
- Прочитайте [Початок роботи](0_Getting_Started.md) для перших кроків.
- Потім повідомте про проблему, як описано вище.
