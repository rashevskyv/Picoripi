## 1. Розкладка

```
+---------------------------------------------------------------------------------+
| File  Edit  View  Tools  Navigation  Bookmarks                         Help     |
+---------------------------------------------------------------------------------+
| Toolbar: Save  Undo Redo  Find  Preview  AI Chat  BFN  Rescan All  Settings  >_  F1 |
+---------------------------------------------------------------------------------+
| Blocks (tree)        | Strings in block (click a line to select)                |
| folders + files      | Hide empty / translated / unsaved / overrides / warnings |
| Speakers, Story, …   +----------------------------------------------------------+
| + − ✎ ↑ ↓ ⟳         | Original (read-only) | tools | Editable translation      |
| Глосарій…            | Max-width, Hide tags |      | Window / Chapter / Speaker |
+---------------------------------------------------------------------------------+
```

| Зона | Що це |
|------|--------|
| Ліворуч | Дерево проєкту: фізичні файли + похідні віртуальні корені. Заголовок: **Blocks:** (підказка про подвійний клік у тултіпі). |
| Праворуч зверху | **Strings in block (click line to select):** список лише для читання. Клік по рядку прив’язує редактори. |
| Ліворуч знизу | **Original** — оригінал, лише читання. |
| Праворуч знизу | **Editable** — єдине поле, куди пишеться переклад. |
| Вузька колонка між Original і Editable | Revert string, Restore translation, Inspect story context, стрибок у Script Markup Studio. |
| Над Editable | **Window:**, **Chapter:**, **Speaker:**, далі **AI Translate**, **AI Variation**, **Auto-fix**, **Font:**, **Max-width:**, **Apply**. |
| Під Editable | Візуальне прев’ю (перемикач **View → Preview**). |

**Не** друкуйте в Original. **Не** вважайте список Strings редактором.

## 2. Перший запуск

1. `File → New Project…` (`Ctrl+N`) або `Open Project…` (`Ctrl+O`).
2. New Project (**Create New Project**) запитує:
   - **Project Name**
   - **Project Location** (тека, де з’явиться `project.uiproj`)
   - **Source Type:** **Folders** або **Files**
   - **Source:** оригінальні файли (або розпакований ISO `root`)
   - **Translation:** копія, куди можна писати
   - **Auto-create translation files**
   - **Game Plugin:** тека в `plugins/` з `config.json`
   - **Description** (необов’язково)
3. Плагіни, які зараз так знаходяться (ім’я теки → **display_name** у `config.json`):
   - `zelda_bmg` — Zelda: Twilight Princess BMG. Однаково для GameCube, Wii і Wii U (HD): **Source** — тека з
     `bmgres*.arc` (`res/Msgus` на GameCube і в розділі DATA диска Wii, `content/res/Msguk` або `Msgus` у HD);
     ідентифікатори повідомлень ті самі, тож мовці, сцени й розмови працюють однаково. У тексті HD є ще іконки
     керування Wii U (`{U:ZL}`, `{U:L stick}`, `{U:+}`…). **Тека шрифтів** — `res/Fontus` (HD: `res/Fonteu`).
     HD малює літери з текстур у `*.pack.gz`, а не з BFN: збирання робочої теки (`TPHD_UA\2_build.bat`)
     перемальовує їх з відредагованих аркушів BFN. **Збірка** (менеджер проєктів): **образ диска GameCube** записує
     перекладений ISO поруч із копією диска, яку майстер записав під час розпакування гри (проєкт, створений раніше,
     такого запису не має: створіть його знову); **мод для Dusklight** записує `Twilight Princess (UA).dusk` і потребує
     вашого диска USA; **графічний пакет Wii U і тека SDCafiine** записує графічний пакет Cemu і теку SDCafiine для
     HD-гри з таблицями розмірів і перемальованими текстурами шрифтів. Диск Wii ще не має цілі збірки: його розділи
     зашифровані, і Picoripi не може їх записати.
   - `zelda_mc` — The Legend of Zelda: The Minish Cap
   - `zelda_ww` — Zelda: The Wind Waker HD (Wii U): `Message/*.msbt` і `Font/*.bffnt`, витягнуті з `content/Common/Pack/permanent_2d_UsEnglish.pack` (один блок на MSBT). Теги взяті з `CKing.msbp` самої гри (`[Red]…[/C]`, `[Name]`, `[Wait:10]`, `[A]`); мовці, ширина вікна (875 одиниць шрифту у вікні розмови, 812 — у табличках і вікнах предметів, 4 рядки на сторінку), розмови й терміни глосарію — з атрибутів кожного повідомлення. Незмінений файл зберігається байт у байт. Load Reference Patch з текою файлів `permanent_2d_<Регіон><Мова>.pack` (тека `reference\` робочої папки: французький та іспанський pack гри і pack російського патча під назвою `permanent_2d_RuRussian.pack`) показує ці мови, російську першою, за файлом і міткою повідомлення. Font Editor: усі шість шрифтів (CKingMsg, CKingMain, CKingMainL, RGBA8-картинки кнопок CKingPic, CKingRuby, CKingZelda). Вікно Textures: зображення BFLIM логотипа, екрана завантаження, екранів кнопок і контролерів (`source\Layout\*.szs`, тобто `content/Common/Layout` гри) і назви на картах та картинки кнопок у pack. Старі проєкти з `.txt` Kruptar теж відкриваються. Майстер приймає англійський пакет або теку гри й розпаковує `Message\`, `Font\`, `Pack\` і `Layout\`; **Зібрати** робить графічний пак Cemu (`graphicPacks\Picoripi_UA_WWHD\`) з змінених повідомлень і шрифтів. Порт для Switch SwitchWakerHD (centollOS, форк ZeldaWWHDRecomp) читає розпаковану гру з `sdmc:/switch/wwhd/game/` під час гри, тож `2_build.bat` робочої теки також пише `build\switchwakerhd\switch\wwhd\game\content\` (перекладений pack і файли `Common/Layout`) для копіювання поверх цієї теки; ті самі файли працюють у Windows-збірці ZeldaWWHDRecomp
   - `paper_mario_cs` — Paper Mario: Color Splash (Wii U, Європа): **Source** — `source\content` робочої папки (`1_unpack.bat` розпаковує туди файли гри `.lz`), один блок на кожен `messages/EU_English/*.msbt` (48 файлів, 6 940 повідомлень). Назви тегів узято з `gojika.msbp` самої гри (`{PageBreak}`, `{wait:30}`, `{select:0:1:0:300:yesno}`, `{ItemName:item}`). Редактор шрифтів показує п'ять `fonts/*.bffnt`; вікно «Текстури» — англійські картинки інтерфейсу `Graphics/UI/**/*.EUR_en.bfres` (логотип, написи боїв, заставки розділів). `2_build.bat` знову стискає змінені файли й записує їхні розміри в `fs.table`
   - `zelda_sshd` — Zelda: Skyward Sword HD (Switch) і оригінал для Wii (один плагін; версію видно з теки джерела): англійські `*.msbt`, які `1_unpack.bat` дістає з архівів `.arc` (`US/Object/en_US/<область>/`, текст інтерфейсу `Layout/<назва>/text/`), один блок на файл. Теги названо за текстом (`{heroName}`, `{color:Red}`, `{item:11}`, `{icon:41}`, `{wait:15}`, `{choice1:65535}`); незмінений файл зберігається байт у байт, а `2_build.bat` пакує файли назад в архіви. Ціль збірки `skyrecomp` (Switch, «SkyRecomp (порт для Windows, тека моду)») пише `mods/Picoripi_UA/romfs/` для порту SkyRecomp: кожне змінене повідомлення пакується у свій `.arc`, змінений шрифт копіюється як є; вона читає сиру теку `romfs` поруч із `source` і відхиляє `exefs/main`, що не є v1.0.0. Мовці (байт мовця в HD, вікно Фай, файли одного персонажа), розмови (потоки MSBF), межі рядка для кожного типу вікна (гра сама рве задовгий рядок посеред слова, тож тримайтеся меж; 4 рядки на сторінку) і терміни глосарія беруться з даних гри. Load Reference Patch з текою `romfs` HD показує офіційну російську першою і ще 12 мов — і для проєкту Wii, за міткою повідомлення. Wii: повідомлення меню HOME (`HomeButton2/home.csv`, англійський стовпець) — теж блок. Tools → Textures показує англійські текстури з текстом (логотипи заставки й фіналу, підписи вступу, Game Over, The End; Wii: банер збереження, попередження про ремінець, написи меню HOME, банер каналу диска `opening.bnr`), а Font Editor — усі шрифти (і шрифт іконок, шрифти меню параметрів HD, шрифти меню HOME і відео MotionPlus на Wii), коли робочий інструмент `tools\ss_extra_sources.py` (у теці HD) поклав їх у `source`
   - `zelda_mm64` — Zelda: Majora's Mask (N64): вихідний файл — сам американський ROM (`.z64`, `.n64`, `.v64`), файл перекладу — перекладений ROM. ROM відкривається чотирма блоками: 4589 повідомлень, 45 повідомлень титрів (коди Ocarina of Time), «Interface strings» — рядки, які друкує сам код гри (назви місць для сови, «Rupee(s)», швидкість часу, кольори коду масок; у кожного фіксоване місце), і «PRESS START» титульного екрана (два слова до 5 клітинок титульного шрифту: цифри, латинські літери, кілька літер із діакритикою); коди керування як `{теги}` (zeldaret/mm); ширина рядка за мапою шрифту гри з Font Editor, коли її збережено в проєкті, інакше за таблицею ширин самої гри, і за типом вікна. Збереження перебудовує файли тексту й таблиці повідомлень із вихідного ROM, лишає текстури, гліфи й ширини, змінені в перекладеному ROM (Інструменти → Textures, Font Editor), і виправляє контрольну суму заголовка. Мовці (один актор на рядок, коли декомпіляція показує рівно одного), сцени й терміни для глосарію беруться з `context.json`, який офлайн створює з zeldaret/mm і ROM команда `python -m plugins.common.zelda64_context`. Українські літери зберігаються в комірки шрифту з `translation_map.json` (проєкту, інакше плагіна): схожі на латинські літери ділять латинський гліф (А = A, і = i, Ї = Ï…), решта займає комірки літер з діакритикою й невживаної пунктуації, дібрані за шириною, тож англійський текст лишається читабельним; Ocarina of Time — за тією ж схемою. Load Reference Patch із текою, де лежить `mm3d_seed.json` (український текст, перенесений із Majora's Mask 3D за ідентифікаторами повідомлень N64), показує його як референс «Ukrainian (MM3D)»
   - `zelda_mm3d` — Zelda: Majora's Mask 3D (3DS, Європа, з оновленням v1040 або без нього). **Source:** тека `source` робочої теки (`1_unpack.bat` копіює туди `romfs\message\eu\eue.gmsg`, шрифт `ltn16.gzf` і текстури з текстом); **Translation:** `translation` (цілі файли за шляхами romfs; `2_build.bat` робить мод LayeredFS, який читають і гра, і оновлення). Усі 6152 повідомлення `eue.gmsg` (діалоги, предмети, таблички, Записник Бомберів, назви місць, титри, вибір файлу, риболовля, Камінь Шейка, завдання), один блок на діапазон ідентифікаторів; невідредагований файл лишається байт у байт. Коди керування — теги з назвами плагіна N64, де код той самий: `{color:red}`, `{box-break}` (після нього розрив рядка), `{quicktext-on}`, `{name}`, `{btn:A}`, `{delay:10}`, `{flow:wait}`, `{event:1}`, `{choices:2}`, `{center}`, `{sfx:0x01006858}`, `{plural:0x0007}…{plural-else}…{plural-end}`. **Load Reference Patch** з `eue.gmsg` російської збірки (або її текою) показує російську; тека гри `romfs\message\eu` — французьку, німецьку, іспанську та італійську. Font Editor відкриває `ltn16.gzf`; вікно «Текстури» показує 129 текстур з текстом: меню й HUD (`layout\EU_English\*.gar`), заставки місць, днів і босів, логотип і копірайт заставки (текстури всередині моделі `.cmb` і анімації `.cmab`), попередження про збереження і мітки версії
   - `zelda_oot64` — Zelda: Ocarina of Time (N64): американський ROM 1.0, так само як `zelda_mm64`: ROM відкривається трьома блоками — 2115 повідомлень, 48 повідомлень титрів і два рядки титульного екрана («PRESS START», «NO CONTROLLER»: по два слова, кожне слово вміщається в клітинки, які малює гра, лише літери й цифри титульного шрифту); коди з zeldaret/oot. Font Editor показує шрифт повідомлень і шрифт титульного екрана та вибору файлу (гліфи кандзі, які гра бере за повідомленням 0xFFFC; ширин у нього немає). Інструменти → Textures показує 335 текстур із текстом (назви предметів, мап і місць, написи паузи й вибору файлу, заставки босів); збереження тексту лишає текстури й шрифти, змінені в перекладеному ROM
   - `jak_and_daxter` — Jak and Daxter (Switch, порт OpenGOAL; Jak 1 NTSC-U, Jak II NTSC-U, Jak 3 PAL, один плагін): **Джерело** — англійський текст гри (`text/common.json`, 781 id у Jak II, один блок, id збережено) і англійські рядки субтитрів (`subtitle/lines.json`, один блок на сцену). Збереження записує лише змінені рядки в англійський overlay порту; `2_build.bat` запускає власний компілятор порту, тож гра читає змінені файли `*.TXT`. У вікні Текстур видно текстури рівнів, експортовані в PNG (`textures/**/*.png`, з файлів `.fr3`; пікселі RGBA та BC1/BC3). Текст іде через англійський overlay, тому український переклад показується в будь-якій збірці без змін інтерфейсу; шрифту Jak у Редакторі шрифтів поки немає.
   - `sly_cooper` — Sly Cooper and the Thievius Raccoonus (порт ProjectCane, Switch, папка даних читається на місці): **Джерело** — англійський текст кожного файлу рівня (`text/<світ>/<рівень>.json`, один блок на рівень, усі текстові рядки у порядку файлу: діалоги, субтитри, сторінки Thievius Raccoonus). Збірка замінює кожен змінений рядок у копії файлу рівня (`build\ProjectCane\Worlds\...`) і перевіряє результат. Зараз записується лише ASCII: рядок з іншими літерами зупиняє збірку. Шрифти і картинки ще не відкриваються; текст меню вшитий у порт. Читачу таблиць рівня потрібен локальний файл схеми опцій, який цей випуск не постачає.
   - `manual_3ds` — Електронні посібники системних програм 3DS (переглядач інструкцій). **Джерело** і **переклад** — папки з одним JSON-файлом на посібник (формат `src/manuals/*.json`: `en` — англійська, `ru` — російська, `ua` — переклад). Це може бути та сама папка (файли читаються на місці): колонка оригіналу показує `ru` (ключі йдуть за російським документом), колонка перекладу — `ua`, а довідкова вкладка **English (EN)** показує `en` лише на сторінках, де англійський текст збігається з російським абзац за абзацом; на будь-якій іншій сторінці вона порожня. Редактор перевіряє кожен абзац так, як його показує консоль: рядки розставляються так само, як збірка для консолі, а вимірюються так, як їх малює консоль (кількість рядків, текстові панелі за стилем, слово ширше за свою панель, рядок, який консоль розриває всередині панелі, рядок за краєм картки, рядок, що заходить на картинку або рамку збоку), а коли в панелі перегляду вказано папку repo_manual, сторінку ще й збирають і малюють з усіх поточних текстів на ній, тож редактор позначає те, що видно лише на намальованій сторінці (рядок, що виходить із залитої клітинки, два абзаци, чиї літери сходяться, рядок, який замальовує намальована після нього панель), плюс маркери, гліфи та кнопкові гліфи (кожен має повернутися, як в російському оригіналі; гліф, що має власну панель, лишається в ній і не входить у переклад). Панель попереднього перегляду — симулятор переглядача консолі: сторінку збирають з поточного тексту так само, як збірка для консолі, і малюють з отриманих файлів розмітки шрифтом консолі, з її картинками, рамками та оформленням (заголовок зі значком номера сторінки консолі, смуга прокрутки, нижня панель); рядок стану називає номер сторінки консолі та дефекти рендера (рядок виходить за край картки на смугу прокрутки, переглядач розірвав рядок усередині панелі, рядок над картинкою чи рамкою, рядок, що починається в залитій клітинці й виходить за неї — білий підпис таблиці виходить із сірої клітинки на білу сторінку, як і на консолі, — два рядки, чиї літери сходяться, рядок, який замальовує панель, намальована після нього, відсутній гліф). Прев'ю перемикається на розмір тексту вибраного рядка (великий чи дрібний); вибраний абзац обведено на сторінці, і сторінка прокручується до нього, якщо його не видно; рядок, що не малює тексту, каже про це в рядку стану. Той самий рендерер працює без вікна: `python scripts/manual_3ds_render.py render <посібник> <сторінка консолі> --size small --out page.png`, `all --out <папка>` (усі сторінки збірки зі списком дефектів), `validate --shots <classification.json> --calib <папка знімків> --out <папка>` (звіряє пари знімків консолі з кожною збіркою й пише HTML-звіт), `table` (номер сторінки консолі, файл `Page_NNN`, назва, категорія).
     **Попередній перегляд.** Перегляд посібника (замість попереднього перегляду BFN) малює сторінку вибраного рядка так, як показує переглядач 3DS: верхній і нижній екрани один під одним, один безперервний стовпець тексту, прокрутка колесом миші або перетягуванням. Кнопка Y (смуга внизу нижнього екрана або кнопка в нижній частині панелі) перемикає великий і малий текст. Текст — поточний переклад; рядок, який рендер позначив дефектом (за краєм картки, розірваний усередині панелі, над картинкою чи рамкою), має напівпрозору червону смугу. Рядок зупиняється перед картинкою або рамкою збоку, як на консолі. Папку вказують кнопкою **Обрати папку...** внизу панелі. У ній лежать архіви посібників власника: вона читається на місці, нічого не копіюється. Проєкт може містити всі посібники (один файл на блок): кожен блок малює власний посібник. Посібник без консольних файлів у цій папці (наприклад `browser`) показує про це один рядок. Картинки малюються зі своїх текстур, а віконні панелі (помаранчеві пункти) — зі своїми рамками-текстурами; панель без текстури заливається її власним кольором. Верхній рядок показує номер сторінки консолі в значку кольору категорії сторінки з «Змісту» та назву з розділу «Зміст» (переклад). Сусідні сторінки на панелі не малюються. Бічна смуга, смуга прокрутки й нижня панель переглядача беруться з вирізок знімків екрана в ігнорованій git папці даних (`<data>/plugins/manual_3ds/chrome`); без них вони малюються пласко.
     **Клік і оригінал.** Клік на абзац у перегляді (натиснути й відпустити без перетягування) вибирає його рядок у редакторі; перетягування прокручує сторінку. Вибирач над переглядом додає оригінал поруч із перекладом. **Оригінал: російська (ru)** малює сторінку так, як її зберігає консоль, з її власними переносами рядків. **Оригінал: англійська (en)** малює англійський текст у російських панелях. Обидва полотна мають спільну прокрутку, розмір тексту і вибраний абзац. Рядок стану показує, як вміщується абзац: його панелі, ширину панелі, скільки рядків потрібно тексту і їхню ширину, та найдовше слово. Проблема слова, кількості рядків або панелей дає ті самі числа; підпис у сірій клітинці каже, скільки панелей має клітинка.
     **Переноси рядків.** Enter вводить жорсткий перенос `{br}`. Перенос рядка, введений іншим способом, на консолі є пробілом: проблема `NEWLINE` його позначає, а її автовиправлення замінює його на `{br}`. Жорсткий перенос займає вільний рядок на консолі; без нього абзац дає проблему рядків.
     **Теки.** Під кожним посібником у дереві блоків: **Small text** і **Large text** (тека на сторінку, назва — заголовок розділу), **Sections** (на розділ: його малий текст, потім великий) і **Contents** (заголовки розділів). Рядок стоїть у двох місцях. Назви розділів беруть поточний переклад запису індексу, або оригінал, коли він порожній. Назви оновлюються після перебудови дерева (після збереження). Вибір теки показує її рядки в списку.
     **Той самий текст.** Абзац, чий текст однаковий у двох посібниках (наприклад, розділ «Здоров'я і безпека»), отримує один переклад; смуга пам'яті й пакетне злиття повторів використовують його. Кожне місце перевіряється першим: якщо текст не вміщається в його панель або кількість рядків, він не записується (смуга стану показує кількість). Великий і малий текст мають спільний переклад; перевірка вирішує для кожного місця (вікі 11, *Одне джерело — один переклад у межах прогону*).

Типові псевдоніми тегів: `{Player}`, `{Rival}`, `{Var1}`–`{Var3}`, `{A}`, `{B}`, `{Start}`, `{Up/Down}`, `{Left/Right}`, `{Plus}`, `{Lv2}`. Ще не в режимі ROM: шрифт і превʼю вікна повідомлення. **Перегляд вікна повідомлення:** для FireRed, LeafGreen і Emerald перегляд малює вибране повідомлення шрифтом самої гри, який читається з базового ROM у фоновому потоці. Текст показано сторінками, з шириною тексту та двома рядками вікна. Рядок, що не вміщується, або третій рядок без прокрутки чи нової сторінки позначається під вікном. Ruby і Sapphire поки без запису шрифту. **Назви з таблиць C-коду:** назви, які читає C-код, стоять у полях фіксованого розміру, тому вони не можуть рости. Вони розпаковуються у власні файли в `text\`: види (412, `species_names.inc`), ходи (`move_names.inc`), здібності, типи, класи тренерів, предмети (`item_names.inc`), імена тренерів (`trainer_names.inc`) і ягоди. Поле, довше за свій розмір, позначає попередження **Byte budget exceeded** під рядком редактора; збірка його відхиляє і називає кількість байтів. У FireRed, LeafGreen, Emerald, Ruby і Sapphire у проєкті вже є описи ходів, здібностей і предметів, назви натур, описи Покедексу та категорії Покедексу. Ці тексти можуть рости: довший текст переноситься в вільне місце, а його вказівник переписується. Назви й описи ягід і декорацій, назви регіонів Тексти, які будує C-код (рядкові літерали декомпіляції), теж є в проєкті, якщо ROM містить кожен текст одним цілим; вони розпаковуються в `text\c_<вихідний файл>.inc`. Тексти інших мов і налагоджувального коду в англійському ROM відсутні, тож їх не включено. Описи предметів з `items.json`, назви полів тренерів і декорацій (кожне місце одного імені є полем одного тексту; вони розпаковуються в новий файл таблиці з назвою вихідного файлу, наприклад `text\c_trainers_h.inc`) та англійські повідомлення ROM, яких немає в жодному вихідному файлі (наприклад, текст мультибут-програм, `text\c_rom_messages.inc`), теж є в проєкті. Зображення, палітри, шрифти й звук не є текстом і не відкриваються.

### Менеджер проєктів

Менеджер проєктів відкривається на старті, якщо жоден проєкт не відкрито. Він показує проєкти, які ви додали. Проєкт
додається, коли ви його створюєте, відкриваєте або імпортуєте.

- **Додавання:** натисніть `+`. Оберіть «Новий проєкт» (майстер), «Додати наявний проєкт» (файл `project.uiproj`) або «Імпорт проєктів з папки». **Файл → Новий проєкт** (Ctrl+N) відкриває той самий майстер.
- **Майстер нового проєкту:** оберіть гру, потім додайте файли. Плагін гри читає кожен файл і визначає його роль (наприклад основна гра або оновлення) і платформу. За потреби змініть їх. Потім оберіть теку проєкту. Оригінали не копіюються: проєкт посилається на них за шляхом. Щоб використати теку перекладу, яка вже є, увімкніть **Використати наявну теку перекладу** і оберіть її; Picoripi тоді не створює в ній файлів перекладу. Гра з одним файлом не має теки перекладу, тому для неї опцію відхилено. Якщо грі потрібне розпакування, майстер розпаковує файли в теку проєкту. «Скасувати» зупиняє розпакування і прибирає те, що було записано. Образ гри, який обрана гра не може розпакувати, відхиляється: майстер про це повідомляє і просить спершу розпакувати образ у теку; нічого не створюється. Проєкт, який не вдалося створити або відкрити, видаляється і не зберігається як останній. На старті останній проєкт, що не завантажився або не рухався дві хвилини, забувається, причину показано, і відкривається Менеджер проєктів. Для образу GameCube або Nintendo DS майстер спершу перевіряє, чи є на диску місце (розмір образу плюс 10 %, або 256 МБ, якщо це більше), і зупиняється до запису, якщо місця бракує. Деяким іграм потрібна лише частина розпакованих файлів: тоді проєкт починається з цієї теки (наприклад Twilight Princess `files/res/Msgus`). Metal Gear Solid: The Twin Snakes бере два диски: додайте кожен диск, і майстер призначить йому роль. Picoripi читає образи GameCube (ISO і NKit), ROM Nintendo DS, програми Nintendo 3DS (`.3ds`, `.cia`, `.cxi`, розшифровані або зашифровані), пакети Switch `.nsp` і диски Wii; образи GameCube і Wii у форматах RVZ і WIA читаються як є (для Wii файл ключів не потрібен: формат зберігає розділ розшифрованим), а `.xci` потребує спершу NSP. Зашифрованим файлам потрібен файл ключів їхньої консолі: `aes_keys.txt` для 3DS (поруч `boot9`, якщо його використовує робоча тека), `prod.keys` для Switch або `keys.bin` для Wii. Майстер просить файл ключів консолі один раз і лише тоді, коли плагін гри розпаковує цю консоль; він запам'ятовує лише місце, де файл лежить. Якщо ви скасуєте це вікно, майстер зупиняється і нічого не створює. Жоден плагін гри ще не розпаковує файли Switch або Wii, тож майстер поки не просить ключ Switch чи Wii. Picoripi не перевіряє хеші розшифрованих даних.
- **Розпаковування:** образ диска GameCube (ISO або GCM) чи ROM Nintendo DS (`.nds`) розпаковується в теку `unpacked` усередині теки проєкту. Picoripi розпізнає файл за вмістом. Плагін гри вирішує, які файли залишити. Образи GameCube у форматах RVZ і WIA читаються як сам диск, який вони містять (файл лише читається: його не перетворюють і не записують; перезбудований диск лишається звичайним ISO). Файли RVZ і WIA дисків Wii читаються так само і не потребують ключа. Файли NKit інших видів не читаються: спершу перетворіть їх на звичайний ISO. Гра, якій розпакування не потрібне, наприклад ROM Game Boy Advance, використовує файл як є.
- **Імпорт:** шукає файли `picoripi/project.uiproj` у папці. Папки з іменами `_…` або `.…` пропускаються. Дублікати й непрочитні проєкти стартують без позначки. Кожна папка серії стає однією папкою менеджера.
- **Папки:** створюйте власні папки. Правий клік по проєкту → «Перемістити до папки». Видалення папки переносить її проєкти на верхній рівень.
- **Порядок:** проєкт, відкритий останнім, завжди зверху. Вибір групування і сортування зберігається.
- **Пошук:** поле **Пошук проєктів** над списком фільтрує під час набору. Ctrl+F переносить курсор туди; Esc його очищає. Пошук іде за назвою проєкту, серією, платформою, плагіном, папкою (групою) менеджера, де лежить проєкт, і шляхом до папки; регістр не має значення, українські й латинські літери працюють. Кожне слово має збігатися з одним із цих полів. Групи без збігів ховаються, а лічильники груп показують збіги. Пошук не читає файли.
- **Закриття:** якщо проєкт не відкрито, закриття Менеджера проєктів (кнопка закриття, Esc або Alt+F4) закриває Picoripi, як «Файл → Вихід». Якщо проєкт відкрито, закриття повертає вас до цього проєкту.
- **Вигляд:** **Список** (типовий) показує рядок на проєкт: значок 64 px, назву, платформу, серію, плагін, прогрес (перекладено з рядків, що потребують перекладу, зі смугою), останнє відкриття і прапорці стану. **Плитка** показує ті самі проєкти як плитки 128 px. Виберіть плитку, щоб побачити її подробиці під сіткою: ті самі, що в розгорнутому рядку списку. Групування діє лише для списку.
- **Значки:** значок проєкту — це `icon.png` поруч із його `project.uiproj`, масштабований до 128 px. Без нього плагін гри може дати зображення; без цього показується кольорова плитка з ініціалами серії. **Змінити значок...** (меню рядка або «Деталі») копіює обране вами зображення, масштабоване до 256 px. **Прибрати значок** видаляє лише цей файл. У майстрі також є необов'язкове поле **Значок**.
- **Сканування і прогрес:** сканування читає картки, значки і підрахунки всіх проєктів в окремому процесі, тому вікно лишається чутливим. Спершу воно читає назви всіх проєктів (близько секунди), тож список і пошук одразу мають усі назви. Проєкт без назви у файлі показується під назвою теки гри (теки над `picoripi`). Поки перевіряються значки й файли кожного проєкту, смуга показує «Перевірка проєктів: 37 з 191...»; далі над списком показується смуга «Сканування 37 з 191 — назва — ще близько 2 хв». **Сховати** ховає смугу, сканування триває; **Скасувати сканування** зупиняє його після проєкту, що рахується; якщо процес не зупиниться за 2 секунди, його завершують. Смуга зникає, коли сканування завершено. Рядки, для яких підрахунку ще немає, показують `…`.
- **Кеш:** другий запуск одразу показує останні підрахунки і сканує знову лише змінене: проєкт, чий файл проєкту, конфігурація плагіна або файл джерела чи перекладу змінився від останнього підрахунку, рахується знову. Так само рахується знову проєкт після зміни Python-файлів його гри, спільних файлів плагінів або після оновлення Picoripi. Інші проєкти зберігають свої підрахунки. Кеш — це `project_index.json` і `pm_icons` у папці даних; їх видалення лише коштує нового сканування.
- **Колонки:** рядки і відсоток перекладу рахуються у фоні, і для проєктів, які ви не відкривали. Блоки в архівах ще не враховуються.
- **Плагін відсутній:** проєкт, чий плагін гри не встановлено, має прапорець **Плагін відсутній** і не рахується. Нічого не видаляється.
- **Деталі:** розгорніть рядок, щоб побачити шлях, файли гри з їхніми ролями, статистику, список папок з блоками і рядками, файли теки джерела за видами (текст, шрифт, текстура, інше; рахуються у фоновому потоці, коли рядок відкрито вперше, і зберігаються, доки Менеджер не закрито) та те, що потребує уваги (наприклад блоки, які ще не мають файлу перекладу). Два прапорці, **Зібрано** і **Перевірено в грі**, ставляться лише тоді, коли ви їх вмикаєте. Деталі також показують глосарії серії, які використовує проєкт (глосарії папок над ним і явне посилання), з кількістю термінів у них, чи глосарій пов’язано або знайдено в теках над ним, і скільки рядків проєкту вже переклала інша гра серії; менеджер їх лише читає.
- **Зібрати мод:** збирає цілі гри в теку `build` проєкту. Якщо гра не оголосила жодної цілі, кнопка вимкнена.
- **Експортувати мод:** копіює зібрану ціль в обрану вами теку. Тека має бути порожньою.
- **Запустити в емуляторі:** збирає ціль і запускає емулятор платформи цієї цілі. Команду кожної платформи задайте кнопкою «Емулятор...» (один рядок на платформу). Напишіть `{path}` там, де має бути зібраний файл або тека, наприклад `"C:\Emu\emu.exe" {path}`. Пункт вимкнено, якщо для платформи немає команди. Діалог «Емулятор...» показує рядок для кожної платформи, яку використовує збірка; рядок без назви з'являється лише для збірки без платформи. Збережена раніше спільна команда діє на кожну платформу, доки для неї не задано власний рядок.
- **Значок гри:** проєкт може показувати картинку своєї гри. Це файл `picoripi/icon.png` поруч із `project.uiproj` (PNG, до 256 пікселів). Без цього файлу картинки немає. Скрипт `scripts/harvest_project_icons.py` дописує відсутні значки з файлів самої гри; наявний `icon.png` він не замінює, а без `--apply` лише друкує таблицю.
- **Прибрати з менеджера** ніколи не видаляє файли проєкту.

## 11. Дерево Blocks (ліворуч)

Кнопки заголовка: додати теку (неактивна, поки немає проєкту), розгорнути все, згорнути все. Ctrl+колесо над деревом змінює шрифт дерева.

**Show Unsaved Only** (над деревом): лише блоки й теки з незбереженими змінами. Лише на сесію; після перезапуску завжди вимкнений.

Тулбар дерева (внизу панелі; кнопки спочатку неактивні):

| Кнопка | Дія |
|--------|-----|
| + | Додати / імпортувати блок |
| − | Видалити вибраний блок |
| ✎ | Перейменувати |
| ↑ / ↓ | Порядок. Drag-and-drop теж переміщує. Alt+Shift+Up/Down **навигує**, не рухає |
| ⟳ | Перебудувати Speakers, Chapters і Items з поточних сюжетних даних. Файли перекладу не чіпає |

**Глосарій…** під деревом відкриває глосарій проєкту (`Ctrl+G`). Ctrl-клік по терміну в Original відкриває той запис.

**Структура та елементи вікна глосарію (Glossary Dialog)**:
- **Ліва панель (Терміни та категорії)**:
  - Вгорі: рядок пошуку для фільтрації термінів у реальному часі.
  - Посередині: вкладки категорій (`_tab_widget`), що групують терміни за темами («Персонажі», «Предмети», «Локації» тощо).
  - Внизу: окрема нижня панель із чекбоксом **Needs review** (`_unconfirmed_only_checkbox`), який фільтрує таблицю, показуючи лише непідтверджені терміни, не захаращуючи рядок пошуку та не забираючи вертикальний простір деталей.
- **Права панель (Деталі терміна)**:
  - **Оригінал і переклад пліч-о-пліч**: синхронізована сітка `QGridLayout` з єдиною висотою 26px. Оригінал (тільки для читання, з можливістю виділення та копіювання) обмежено максимальною шириною 280px та оснащено інтерактивною кнопкою **Wiki ↗** для швидкого пошуку в лорі гри (через `BaseGameRules.get_external_reference_url`). Поле перекладу має компактну кнопку підтвердження **Confirm**.
  - **Виділений рядок дій**: розташований безпосередньо під полем перекладу, надаючи полю введення повну ширину (до 400–550px+). Містить яскраву кнопку **Save** (`Ctrl+S`, підсвічується синім `#2563eb` за наявності незбережених правок), **Confirm translation** (перехід до наступного непідтвердженого терміна) та **Discuss with AI…** (відкриває чат із повним контекстом терміна).
  - **Захист від випадкової втрати незбережених змін**: діалогове вікно підтвердження (`Save` / `Discard` / `Cancel`) з'являється при переході на інший рядок, перемиканні вкладок або закритті вікна з незбереженими правками.
  - **Опис та нотатки**: заголовок секції містить чекбокс **Profiled via AI** зі спливаючою підказкою про статус профілювання мовлення персонажа.
  - **Згортання панелей**: секції «Опис», «Нотатки AI» та «Входження» мають кнопки згортання/розгортання (`[▼]/[▶]`) для економії вертикального простору екрана.
  - **Роздільна фільтрація входжень**: незалежні чекбокси для текстових згадок (**Mentions**) та діалогових реплік персонажа (**Spoken**).
  - **Відповідність рядків референсу та попередній перегляд входжень**: для кожного діалогового входження відображається повне повідомлення оригіналу та повний відповідний референсний запис для цього (block, string) без обрізання оточуючих рядків. Довгий перегляд прокручується вертикально, навіть коли входження лише одне. Входження підсвічується у повному оригіналі, а збіги терміна підсвічуються у рядках референсу зі збереженням усіх переносів рядків. Блок `RU:` виводиться лише тоді, коли референс явно позначений як російський; інші завантажені мови слугують контекстом для AI-перекладача і не маркуються як `RU:`.
  - **Застосування варіантів на місці та DoubleClick**: подвійний клік по запропонованому варіанту або натискання **«Застосувати вибраний варіант»** підставляє переклад у поле редактора та оновлює нотатки на місці без переходу на наступний пункт. Підтвердження терміна та перехід до наступного рядка відбуваються окремо — після явного натискання **«Підтвердити переклад»**. Референсні варіанти зі сторонніх патчів стилізовані окремо (блакитний/курсив) і захищені від випадкового застосування.
- **Нижня панель дій**: містить **Force Retranslate...** (виділено помаранчевим кольором `#ea580c`, автоматично створює бекап `glossary.json.bak` перед переперекладом через ШІ) та кнопку **`[☁ Companion Sync...]`** для синхронізації в 1 клік із [Picoripi Companion](12_Picoripi_Companion.md).

Правий клік (порожнє місце): **Create Folder**, **AI: Translate All Blocks (UA Chronological)**, **Revert All Blocks to Original**, **Restore All Translations**.

Правий клік по файлу: імпорт, зберегти цей блок, rescan, ширини, маркери, restore. Корінь **Chapters** і теки Act не мають контекстного меню (структура лише для читання).

Рядок стану (низ вікна): шлях Original, шлях Changes, ім’я плагіна, `Strings: N | Unbound: N`, далі курсор Pos / Line / Width.

## 12. Strings in block (праворуч зверху)

Клік по рядку одразу прив’язує Original + Editable. Прев’ю BFN з’являється приблизно за кадр. Глосарій, спелчек, теги й попередження наздоганяють після паузи в наборі (~1,5 с). Сам список лише для читання.

| Чекбокс | Ефект |
|---------|--------|
| Highlight moved | Підсвітити рядки, уже в віртуальній категорії. Схований, поки категорії не застосовні |
| Hide moved | Сховати ті рядки з батьківського вигляду. Так само сховано, поки не треба |
| Hide empty strings | Згорнути підряд порожні рядки в плейсхолдер |
| Hide translated | Сховати вже перекладені |
| Show Overrides Only | Лише рядки з власним шрифтом або шириною |
| Show Unsaved Only | Лише рядки з незбереженими змінами. **Після перезапуску завжди вимкнений** |
| Show Warnings Only | Лише рядки з вибраними типами попереджень |
| **Warnings: X / Y** | Які типи попереджень бере фільтр. X = вибрані типи, Y = типи увімкнені в Detection |

Фільтри можна комбінувати. **Не** лишайте **Show Unsaved Only** увімкненим і не вважайте файл порожнім — зніміть галочку.

## 13. Original, вкладки референсу та Editable

**Панель джерела (ліворуч)**

- **Динамічні вкладки референсу**: коли шлях до референсного патчу або мультимовного ROM / ISO налаштовано у параметрах проєкту (**Settings → Project → File Paths → Reference Translation / ROM Path**), панель динамічно генерує вкладки для порівняння (`Original (EN)`, `Russian (RU)`, `German (DE)`, `French (FR)`, `Italian (IT)`, `Spanish (ES)`). Образ гри, який плагін спершу розпаковує (RVZ або ISO іншого регіону), читається у фоні в папку проєкту; ця папка й стає шляхом довідки.
- Лише читання, виділення тексту та повністю синхронізована прокрутка й курсор між усіма мовними поданнями.
- **Max-width:** клік по значенню копіює його в поле Max-width перекладу, далі **Apply** праворуч.
- **Hide tags** (`Ctrl+Q`): перемикає видимість керівних кодів у всіх вкладках оригіналу й перекладу.

**Колонка іконок** (між панелями)

| Кнопка | Дія |
|--------|-----|
| Стрілка (`→`) | **Copy active source string** — копіює текст із тієї мовної вкладки, яка відкрита на даний момент (Original або референс), безпосередньо в цільовий редактор перекладу |
| Документ+стрілка | **Restore translation** — останній бекап (`Ctrl+Shift+T`) |
| S | **Inspect story context** (`Ctrl+I`) |
| R | **Open in Script Markup Studio** — стрибок до місця в розміченому скрипті |

**Editable (праворуч)**

- Сюди друкуєте.
- **Синхронізація вертикального рівня (Y)**: фільтр подій `HeaderSyncFilter` динамічно обчислює `left_header.height = right_header.height - tab_bar.height`, гарантуючи, що верхній край тексту редакторів з обох сторін починається на абсолютно однаковій вертикальній лінії на будь-яких моніторах і масштабах DPI.
- Під ним: візуальне BFN-прев’ю (якщо Preview увімкнений) і панель типу вікна, якщо плагін це вміє.

**Не** застосовуйте Font / Max-width без **Apply**. **Apply** активна лише поки є незастосована зміна.

## 14. Story Context і контрольні елементи (над Editable)

Організовано в компактну 2-рядкову панель над редактором перекладу:
- **Рядок 0**: `Window:` і `Chapter:` ліворуч; навігація (`[↓][↑]`), `AI Translate`, `AI Variation` та `Auto-fix` праворуч.
- **Рядок 1**: `Speaker:` ліворуч; `Font:`, `Max-width:` і `Apply` праворуч.

| Поле | Поведінка |
|------|-----------|
| **Window:** | Тип вікна повідомлення з даних гри. Подвійний клік по підпису відкриває фізичний блок |
| **Chapter:** | Призначити рядок розділу/сцені Story, зокрема без лінку зі скрипта. Подвійний клік — віртуальний Chapter |
| **Speaker:** | Редагований комбо з автодоповненням. **Enter** зберігає ім’я (`save_speaker_for_current_string`). Клік по пункту списку сам по собі не зберігає. Подвійний клік по підпису — віртуальний Speaker або Item |
| **Font:** | Перевизначення шрифту для рядка |
| **Max-width:** | 0 = типово з плагіна. Правий клік: **Reset to Plugin Default**, **Set Width from Original** |
| **Apply** | Зберегти Font і Max-width для цього рядка |

`None` у Speaker знімає призначення. Порожній BMG-паддинг не потрапляє в Speakers; не вигадуйте спікера для тих слотів.

## 17. Чого не робити в головному вікні

- Не редагуйте Original.
- Не вважайте порожній список Strings багом, поки не зняли **Show Unsaved Only** і **Hide empty strings**.
- Не робіть Revert файлу змін, якщо не хочете стерти переклади.
- Не пропускайте Save перед `>_`.
- Не ставте Parallel Requests вище за кількість Active-акаунтів на дашборді локального проксі.
- Не запускайте глосарій / merge / пакетний переклад без налаштованого провайдера.
- Не трактуйте порожні слоти BMG як «неприв’язаний діалог» — вони лишаються лише у фізичному файлі.
