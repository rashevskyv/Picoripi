# Walkthrough: WP1 — транспорт і стійкість JSON (v0.3.143-dev)

План: `docs/audit/2026-10-01/PLAN.md`, розділ WP1. Галочки: `docs/audit/2026-10-01/TASKS.md`.

## Що зроблено

- **1.1** `core/translation/transport.py`: види помилок (`ErrorKind`), `TransportError`, `classify()`
  (винятки `requests`, HTTP-статус, статус, який переказав проксі, `Retry-After`, маскування `?key=`),
  `TransportPolicy` (експоненційна пауза, повне дотримання `Retry-After`, загальний ліміт часу, паузу можна
  скасувати), запобіжник `CircuitBreaker`. Мертві `retry.py` і `concurrency.py` видалено.
- **1.2** Усі непотокові запити провайдерів ідуть через політику. Порожня або не-JSON відповідь — помилка, а
  не «тихий успіх». Шлях Gemini з власним URL використовує той самий код, що й OpenAI-сумісний (отримує
  `think`). Діалог повтору чекає стільки, скільки попросив сервер. Автоповтор (один) є лише в перекладі й
  лише для швидких збоїв; запит, що завершився тайм-аутом, удруге автоматично не надсилається. Конвеєр
  глосарію лишився без клієнтських повторів — як і було задумано.
- **1.3** `utils/json_extract.py` замість трьох «чистильників»: пошук першої цілої JSON-структури потрібного
  типу, лагодження (кома в кінці, фігурні лапки, сирі переноси рядків), розпізнавання обрізаної відповіді.
  Нечитабельна відповідь дає `ParseError`, а не `[]` чи `""`.
- **1.4** Паралельний переклад фрагментів працює через `run_pool`: один невдалий фрагмент не знищує блок,
  готові фрагменти зберігаються, повтор надсилає лише невдалі; фатальна помилка або скасування зупиняють
  подальші запити. Відповідь із переставленими чи чужими `id` відхиляється.
- **1.5** Профіль провайдера: власний OpenAI-сумісний ендпоінт вважається проксі Web2API (`think`, тайм-аут
  не менше 180 с, кількість потоків не більша за кількість активних акаунтів із `/healthz`); хмарні API
  `think` не отримують. Єдине `MAX_CONSECUTIVE_FAILURES = 3`.
- **1.6** Обробники, що застосовують відповідь: перевірка форми на вході, будь-який збій стає помилкою AI,
  група undo завжди закривається.
- **1.7** `ai_traffic.log` — JSON Lines у теці налаштувань: спільний `request_id` для запиту й відповіді,
  номер фрагмента, спроба, розміри, тривалість, вид помилки; запис під блокуванням; ротація при 8 МБ замість
  очищення; підсумок запуску (кількість, p50/p95, збої за видами).
- **1.8** Скасування запиту, що вже чекає на відповідь: робочий потік відмовляється від нього за частки
  секунди (перевірено на локальному сервері із затримкою 5 с).

## Поза планом

- **Знайдено й усунуто причину нестабільності тестів.** Прибирання після кожного тесту
  (`tests/conftest.py::_stop_lingering_qthreads`) іноді викликало `quit()` на головному потоці; після цього
  кожен цикл подій Qt на тому воркері завершувався миттєво — вікна не активувались, таймери не спрацьовували.
  Знайдено відтворенням порядку тестів одного воркера в одному процесі та поділом навпіл. Падав приблизно
  кожен третій повний прогін; після виправлення — жодного.
- **Версію Qt у `requirements.txt` приведено до фактичної** (PyQt6 6.11.0 / Qt 6.11.1).
